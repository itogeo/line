How Snowline works

Free satellite imagery in, a snow map of SW Montana out. This page covers every step, how the map is checked against ground stations, and where it goes wrong.

Area and imagery

The map covers 112.6°W to 109.6°W and 44.55°N to 46.35°N: the Bozeman area, the Tobacco Root, Ruby, Madison, Gallatin and Crazy ranges, the Absaroka Range south toward Yellowstone, and Cooke City. That is twelve 110 km Sentinel-2 tiles (12TUQ to 12TXS).

Sentinel-2 is the European Space Agency's pair (now trio) of optical satellites. Each one repeats its ground track every 10 days. Together they pass over some part of the area most days, and over any one tile every 2–5 days. Snowline uses the Level-2A product, which is surface reflectance corrected for the atmosphere, from ESA's Collection 1 reprocessing.

Finding the scenes

Snowline doesn't call a search API. It runs one SQL query with DuckDB against the S2 STAC GeoParquet index, a static copy of Element 84's Earth Search catalogue published by Taylor Geospatial / TGE Labs on Source Cooperative. Each row is one scene, and its assets column holds the URLs of that scene's Cloud-Optimized GeoTIFFs on AWS.

  • The index for a year is items.parquet plus monthly live-MM.parquet files for recent scenes. Snowline reads the year's list of files from YYYY.json, so the newest scenes are never missed.
  • A scene ESA reprocessed can appear twice until the next fold. Snowline keeps the newest s2:generation_time.
  • A tile is sometimes imaged twice on one day, by two satellites or two orbits. Snowline keeps the copy with the least nodata, then the least cloud.

The code is lib/s2index.py. The Scenes table lists every scene this produces and links each one to its files.

From pixels to snow

  1. Read four bands and the classification. For each tile, Snowline reads the green (B03, 10 m), red, blue, shortwave-infrared (B11, 20 m) and scene classification (SCL, 20 m) windows covering the area.
  2. Convert to reflectance. Collection 1 stores DN = 10000 × reflectance + 1000 (the asset's raster:bands scale 0.0001, offset −0.1). Snowline removes the offset before doing anything else. Skipping this step would push every snow index value toward zero.
  3. Mosaic onto one grid. Tiles are reprojected to a 0.0003° latitude/longitude grid (about 24 m × 33 m here) and stitched together. Where tiles overlap, the first tile with data wins.
  4. Mask cloud and no data. A pixel is masked if ESA's classifier calls it no data (0), cloud shadow (3), cloud medium or high probability (8, 9) or thin cirrus (10).
  5. Normalized Difference Snow Index. Snow is bright in green and dark in shortwave infrared. Cloud is bright in both. 
    NDSI = (green − swir16) / (green + swir16)
snow  = (NDSI ≥ 0.4  or  SCL = 11)  and not masked
    0.4 is the standard threshold from the MODIS and Landsat snow products (Hall et al., 1995; Dozier, 1989).
    Why SCL too: on shaded midwinter slopes green reflectance can drop to 2–5%, and the index falls below 0.4 over deep snow. ESA's classifier (class 11, snow) uses more tests and catches many of those pixels. Adding it raised agreement with SNOTEL on the 14 dates we tested from 75% to 87% of station-days, without adding any false snow.

The latest view

One satellite pass rarely sees the whole area. Each orbit images a strip about 290 km wide that cuts across the map at an angle, and clouds take bites out of it. A one-day map is often half hatched.

So by default the map shows the latest view. Every pixel shows its most recent clear look (snow or bare ground) from any pass in the 10 days up to the selected date. A pixel that no pass has seen clearly in those 10 days stays grey (cloud) or hatched (no imagery). The panel says which passes went into the view and how much of it comes from the selected day. This pass only switches back to a single day's pass.

The trade-off is honest age: in the latest view, some pixels can be up to 10 days old. Each published GeoTIFF of the latest view carries a second band with the age of every pixel in days.

Checking it against SNOTEL

The NRCS SNOTEL network measures snow depth daily at 46 stations in and around the area. For each date with a map, Snowline reads the map at every station (a 3×3 pixel window, about 70 m) and compares it with that day's depth:

  • Depth ≥ 2 in and the map shows snow, or depth 0 and the map shows bare ground: agree.
  • Depth ≥ 2 in and the map shows ground: miss. Usually trees hiding the snow (see below).
  • Depth 0 and the map shows snow: false snow.
  • Cloud at the station, or a depth of exactly 1 in: not counted.

A station is one point and a pixel is about 800 m², so perfect agreement isn't expected. Many SNOTEL sites sit in small clearings inside forest, which is the hardest place for an optical satellite to see snow. Per-date results are in snotel_agreement.json.

Lidar terrain

The shading under the snow comes from airborne lidar: laser measurements of the ground surface flown for the USGS 3D Elevation Program (3DEP), published as 1 m elevation models. About 660 lidar tiles cover more than 90% of the area. Most are from the Montana statewide collection, flown in phases from about 2021 to 2023. Yellowstone was flown in 2020.

  • Snowline reads each tile at 4 m, shades it with a low northwest sun and a softer western light, and only then reprojects it. Shading after reprojecting leaves stripes.
  • Where two surveys overlap, the most recently flown one wins.
  • The shading is transparent on flat and sunlit ground and tints shadowed slopes a cool slate blue. Snow is always drawn above it, so the snow stays the brightest thing on the map.

It's there to make the snow readable (which gully, which face, where the tree line is), not to rate slopes. The 3D view still uses Mapbox's terrain model.

Where it goes wrong

Forest canopy

Under dense conifers the satellite sees needles, not the snow below. Forested slopes can show as bare when the ground is white. Turn on the Forest layer (ESA WorldCover) to see where this applies. This is the most common cause of a miss.

Terrain shadow in midwinter

From November to January the sun is low over Montana at the ~11:30 am overpass. North-facing slopes sit in shadow, reflectance is low in every band, and the index gets noisy. Adding ESA's snow class recovers much of this, but snow in deep shadow can still be missed. Spring maps are the most reliable.

Cloud and snow confusion

ESA's classifier sometimes calls thin cloud snow, or calls bright snowfields cloud. Thin cloud that passes the mask can turn up as patchy false snow. Fresh snow on a cloudy morning is the classic case.

Thin or patchy snow

A dusting, or snow between sagebrush, mixes with dark ground inside one pixel. The pixel may fall under the threshold. The map shows where snow dominates a 24 m pixel, not every flake.

Lakes and ice

Frozen, snow-covered lakes are correctly snow. Clear black ice and open water are not. Hebgen and Hyalite can look odd during freeze-up.

Partial days

On many days only part of the area is under the satellite's swath, and the rest is hatched. The coverage bar on the map says how much was imaged.

How often it updates

Every morning (5 am Mountain) a GitHub Action rebuilds the list of passes from the index and refreshes SNOTEL. Two hours later, every pass from the last 10 days that imaged at least 10% of the area, cloudy or clear, is processed into a map, uploaded, and only then added to the timeline. Cloudy passes still show their imagery; the snow layer marks the cloud. Season maps run October to May. The index itself refreshes daily at 03:42 UTC.

Reproduce it

Everything above is open source. To find the scenes behind any date:

pip install duckdb
python -c "
import duckdb
print(duckdb.sql('''
  INSTALL httpfs; LOAD httpfs; SET s3_region='us-west-2'; SET s3_url_style='path'; SET TimeZone='UTC';
  SELECT id, \"eo:cloud_cover\", json_extract_string(assets, '\$.green.href') AS green
  FROM read_parquet('s3://us-west-2.opendata.source.coop/tge-labs/s2-stac-geoparquet/sentinel-2-c1-l2a/year=2026/*.parquet')
  WHERE _tile = '12TVR' AND datetime >= '2026-04-19' AND datetime < '2026-04-20'
'''))"

To rebuild a map from scratch, clone the repository and run:

pip install -r snowline/pipeline/requirements.txt
python snowline/pipeline/fetch_bands.py --date=2026-04-19
python snowline/pipeline/process_tiles.py --date=2026-04-19

The code is at github.com/itogeo/line. The Data page has a reproduce button on every scene.

Snowline's own maps are open data too. Each date is published as single-band Cloud-Optimized GeoTIFFs (0 ground, 1 snow, 2 cloud, 3 no data; EPSG:4326) in a static STAC catalog. Open it in QGIS, or with any STAC client:

import pystac, rasterio
item = pystac.read_file("https://line.itogeospatial.com/snow/stac/snowline-snow-cover/2026-10-03/2026-10-03.json")
with rasterio.open(item.assets["class_r1c1"].href) as src:
    snow = (src.read(1) == 1)
